# Build audit and corrections

## Scope

Audit of this newly created local simulator, not an independent security audit. It is synthetic-only; do not use it for actual financial decisions.

## Findings addressed

1. **Leakage risk:** Split records chronologically before fitting. Preprocessing and both model fits use only train. Model selection uses validation AP; the cutoff uses validation scores. Tests assert temporal separation, selection and threshold calculation. Test data are visible during development and are not an independent final benchmark.
2. **Class-imbalance / accuracy illusion:** Report precision, recall, flagged workload, confusion counts and average precision rather than claiming high accuracy. Undefined precision is shown as a dash. Probabilities are not claimed calibrated.
3. **Threshold and capacity confusion:** The 5% target is selected on validation, not guaranteed in test or new data. Ties and distribution changes may alter workload. The UI labels the held-out cohort and explains slider-driven test exploration.
4. **Source-data overclaim:** All data and labels are generated by invented rules. Prior activity is a sampled feature, not reconstructed history. The UI, README and report explicitly prohibit use on real transactions.
5. **Explanation overclaim:** The Inspect button recomputes the score after one-feature-at-a-time reference replacements. It is labeled a sensitivity, not causal explanation, SHAP or proof. References come only from training.
6. **Uploaded-file risks:** Validate file size, row count, UTF-8, headers, categories, numeric bounds and finite amounts. Use textContent for browser rendering of file names and IDs. Uploaded labels are not used. File upload can spool to temporary disk and is not advertised as memory-only.
7. **Local exposure:** Bind to loopback; restrict Host and browser Origin; add CSP and basic security headers. These are defense-in-depth only, not authentication or a production security design.
8. **Stale application / startup:** Check port before launching and wait for successful startup before opening browser, so the default doesn't intentionally open an old app on an occupied port. A port-binding race remains possible.
9. **Reproducibility:** Fixed random seed, explicit feature list, split and documented library environment. Exact numerical results may vary with dependencies/platforms; dependency ranges are not a lockfile.
10. **API test realism:** Tests use actual locally trained scikit-learn models with FastAPI TestClient, not a mocked ML prediction. Browser smoke tests are separate from pytest.

11. **UI corrections:** Fixed mobile page overflow, added a horizontal-table hint, reduced the displayed queue from 100 to 25, placed sensitivity details near the queue, and clear stale results when CSV scoring fails. Browser smoke tests covered these flows.

## Remaining risks

Synthetic results cannot establish real-world usefulness; no actual calibration, delayed labels, drift monitoring, fairness assessment, costs, identity linking, deployment, audit trails, secure multi-user access or external data validation. One development machine and browser do not validate all operating systems. Dependencies are not pinned to exact versions. Provider APIs are not used. Input size limit is checked after multipart parsing; the web server is intended only for trusted local use. Do not commit private CSVs or run against real customers. For release-quality software, add dependency locking, more platform tests, request-body limiting and a security review.
